# Feuille de route

Ce document relie la **vision** du projet aux **issues** GitHub et aux **endroits du code** où chaque
évolution s'insère. Il est tenu à jour avec les issues : en cas de doute, les issues font foi.

_Dernière mise à jour : 22 novembre 2026._

## Vision

Faire évoluer Jeu Aris d'un jeu d'esquive sur trois voies vers un véritable jeu automobile :
plusieurs modes (trafic, course sur circuit, conduite libre, défis de nitro), des environnements
variés, une conduite crédible et une progression motivante. Voir l'épopée
[#15](https://github.com/digitaleflex/jeu-aris/issues/15).

## Points à arbitrer

- **Deux épopées se recouvrent** : [#15](https://github.com/digitaleflex/jeu-aris/issues/15) (vision
  multi-modes) et [#31](https://github.com/digitaleflex/jeu-aris/issues/31) (écran d'accueil et choix du
  mode). La seconde est en grande partie livrée ; il reste à décider si elle devient une sous-issue de
  la première ou se ferme.
- **Une seule voie, plusieurs voies, ou voies de largeurs différentes ?** `#28` demande un modèle de
  parcours général ; la base actuelle gère seulement N voies égales.
- **Licence** du code et provenance des images : à décider avant toute redistribution (voir le README).

## Principes pour contribuer à la feuille de route

1. Une évolution = une issue qui décrit le comportement attendu, des critères d'acceptation et, si
   possible, une maquette.
2. Elle s'insère dans la couche existante la plus proche (voir [`ARCHITECTURE.md`](ARCHITECTURE.md)).
3. Elle vient avec ses tests ; une règle de jeu ajoutée sans test n'est pas terminée.
4. Un changement volontaire de comportement met à jour le test de caractérisation dans la même PR.
